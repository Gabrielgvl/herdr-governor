## Invariant inventory

Legend: `keep`/`drop`/`ask` + one-line reason. `[EXT]` marks invariants that exist
because of external Herdr or agent-CLI quirks — these are hard-won behavior and must
survive the rewrite as *requirements*, even though the implementation may change.

### A. Activation, hosts, and environment

1. Outside `HERDR_ENV=1` the surface registers/serves nothing: no tools, sockets, timers, or CLI calls. (ADR-001, ADR-025; `src/mcp/host.ts:100`, `index.ts:119`) — guards a stray process acting as Herdr authority outside the runtime — **keep** — cheap, prevents phantom authority.
2. MCP startup refuses without valid injected `HERDR_WORKSPACE_ID/TAB_ID/PANE_ID`, except delegated-executor mode which requires a per-call `caller {paneId, projectRoot}`. (ADR-001/025/038; `src/mcp/host.ts:97`, `src/mcp/run.ts:129,152-157`) — guards unclaimed identity — **keep**.
3. Project dir = valid `HERDR_PROJECT_DIR` else server launch dir; must be absolute, single-line, non-root, existing, realpath-canonical; set-but-invalid refuses, never re-anchors. (ADR-025; `src/mcp/host.ts:113-139`) — guards wrong-root operations — **keep**.
4. One daemon per user: single-instance lock + connect-probe before bind; answered socket refuses, `ECONNREFUSED`/vanished path unlinked and rebound, other errors fail. (ADR-038; `src/daemon/server.ts:262-314`, `instance.ts`) — guards split-brain daemons — **keep**.
5. `daemon.sock` binds only after intent recovery + mailbox + reattach sweep complete; a failed sweep drains any bound supervisors in the fixed shutdown order before refusing. (ADR-038; `src/daemon/main.ts:259-329`) — guards a mid-sweep launch being rewritten to `unresolved` — **keep**.
6. Daemon unreachable → callers get typed `DAEMON_UNAVAILABLE`; never an in-process fallback. (ADR-038; `src/tool-surface.ts:97-98`) — guards silent mode drift — **keep**.
7. Systemd unit ships inert; activation is an explicit owner runbook step, never the repo's. (ADR-038; `README.md:114-127`) — guards surprise background mutation — **keep** (process rule).
8. Shutdown order is fixed: flush handoffs → stop supervisors → `lastStoppedAt` → close server → release lock; zero Herdr writes during shutdown; heartbeat stops first. (ADR-038; `src/daemon/main.ts:345-370`) — guards orphaned supervision and lost state — **keep**.
9. Socket handshake: first line `hello`, version match → `ack`, mismatch → exactly one bounded `PROTOCOL_MISMATCH` then close; malformed line → one bounded error line then close; replies correlated by `id` per connection. (ADR-038; `src/daemon/server.ts:133-221`) — guards cross-talk and confused clients — **keep**.

### B. Herdr CLI / socket as sole authority [EXT-heavy]

10. Every Herdr mutation goes through the installed `herdr` CLI as an argv array with `shell:false`; no shell strings, no synthesized IDs, no reimplemented protocol for mutations. (SPEC.md:47-60; ADR-001) — guards invented identifiers and injection — **keep** [EXT].
11. Bounded timeouts + `AbortSignal` on every CLI call; SIGTERM then SIGKILL after a grace window for stdin children; settle records `exit` before `close`. (SPEC.md:53-55; `large-agent-communications.md:137-143`) — guards wedged children pinning a call — **keep**.
12. Malformed/incompatible CLI output is a typed protocol failure, never guessed. (SPEC.md:57-58) — guards silent misparse — **keep**.
13. Authoritative post-state is re-read after every mutation. (SPEC.md:60) — guards stale success claims — **keep**.
14. Herdr has no compare-and-send/close: preflight+post-state is bounded but non-atomic; the residual race is documented, never hidden. (SPEC.md:64) — guards false atomicity claims — **keep** [EXT].
15. Prompt delivery uses the Herdr supervision socket `agent.prompt` at protocol 22 (ADR-024; `src/agent-prompt.ts:41,138`), one request per connection, `not_written`/`rejected`/`acknowledged`/`unknown` dispatch states — **keep** [EXT] (Herdr 0.8.2 answers one request per connection; `pane_exited` carries no occupant identity — see I-6).
16. Native manager→child follow-ups use raw `herdr agent prompt <TARGET> <TEXT>` positional; large content travels via an owner-only `herdr-handoffs/<runId>/followups/<seq>.md` (0600) pointer file, never argv. (ADR-038 C8; `durable-supervisor.md:86`; `README.md:112`) — guards argv size/privacy limits — **keep** [EXT].
17. A `devin`-kind follow-up sends only to a freshly re-read `idle`/`done` pane; `working`/`blocked`/unknown/unproven defers, never sends. (ADR-038 C8; `durable-supervisor.md:86`) — guards composer-queue loss — **keep** [EXT] (Devin composer queue does not drain at turn end; ADR-029).

### C. Identity and targeting

18. `TargetRef` is exact stable ID, `current`, exact pane label, or unique agent name only; `TARGET_NOT_FOUND`/`TARGET_AMBIGUOUS`/`TARGET_TYPE_MISMATCH`; no fuzzy, prefix, display-number, or focused-pane fallback. (SPEC.md:68-79) — guards wrong-agent mutation — **keep**.
19. `current` means the caller's context, never UI focus. (SPEC.md:70) — guards focus-targeting mistakes — **keep**.
20. Exact child identity = pane ID + terminal ID + agent name + agent kind + all four `agent_session` fields; a pane/name/kind match alone is never coverage. (ADR-019/020; `docs/specs/identity-bound-supervision-and-wait-review.md:78-86`) — guards pane-ID reuse misattribution — **keep** [EXT: Herdr reuses pane IDs].
21. Daemon verifies the claimed caller identity against exactly one fresh `session.snapshot` per request: exactly one pane with claimed `paneId`, occupant `agent_session` equal to claim, tab/workspace parents match; else `CALLER_IDENTITY_*` refusals before any effect. (ADR-038 §5/D2a; `src/daemon/runtime.ts:365-399`) — guards forged caller claims — **keep**.
22. Same-UID identity is cooperative, not cryptographic; stated as such, never implied otherwise. (ADR-038; `durable-supervisor.md`) — guards false security claims — **keep**.
23. Sender identity resolves from the fresh authoritative snapshot (agent name → pane label → kind → pane ID, ID always included); absent caller pane → `SENDER_IDENTITY_UNAVAILABLE`. (ADR-005; SPEC.md:150) — guards spoofed provenance — **keep** wherever sends exist.
24. Sends to the caller's own pane are refused (`SELF_TARGET_REJECTED`). (SPEC.md:150) — guards self-deadlock loops — **ask** (was `herdr_communicate`-only; does the rewrite have a send operation at all?).

### E. Prompt submission semantics [EXT]

29. Text is submitted at most once: no second submission, no separate Enter, no wait, no retry under any acknowledgement uncertainty. (ADR-013 retained by 015/016/021; SPEC.md:196) — guards duplicate-prompt effects after ambiguous transport — **keep** [EXT].
30. A submission is confirmed only by a typed `agent_prompted` ack matching the full captured identity plus interactivity proof (`interactive_ready` or known live `agent_status` with `launch_pending` absent/false); malformed/mismatched ack is terminal. (ADR-013; SPEC.md:179) — guards "sent but unproven" being reported as delivered — **keep** [EXT].
31. The ack proves Herdr accepted the bytes, not that a turn started or finished; post-ack observation is diagnostic-only and never triggers resubmission. (ADR-013; SPEC.md:181) — guards mistaking acceptance for consumption — **keep** [EXT].
32. Launch requires post-ack semantic confirmation: sequential `agent get` + `pane get` polls for ≤5,000 ms at 100 ms cadence; a known working/non-working state confirms only with strictly advanced `state_change_seq` and non-regressed `revision`; timeout/replacement/contradiction → `LAUNCH_FAILED`/`PROMPT_UNCONFIRMED`. (ADR-015/016; SPEC.md:196) — guards reporting success on a never-consumed prompt — **keep** [EXT].
33. `screen_detection_skipped` is diagnostic metadata only — never confirms, contradicts, or rejects. (ADR-015/024; SPEC.md:196) — guards headless false-negatives driving retries — **keep** [EXT].
34. `PROMPT_UNCONFIRMED` means "not proven, possibly consumed": no retry, no cleanup, no recipient registration, no relaunch, no dependent work; child + supervisor + evidence retained; fixed recovery guidance string. (ADR-015/020; `docs/specs/identity-bound-…:220-224`) — guards double-dispatch of a live assignment — **keep**.
35. Turn control `cancel`/`interrupt`: strict working-state identity across snapshot + fresh `agent get`, exactly one `esc`/`ctrl+c`, ≤5,000 ms wait, independent final snapshot; disappearance never means cancel success (`CANCEL_UNCONFIRMED`); `interrupt` reports `agent_exited` only via `post_dispatch_absence_proven`. (ADR-014; SPEC.md:184-199) — guards unverified destructive control — **ask** — no current surface exposes it; decide whether the rewrite needs it.
36. After a successful supervision bind, no later launch failure may release/cancel/shut down the supervisor. (ADR-020 §5.3) — guards identity-proven children losing observation — **keep**.
37. A bind that fails (incl. settlement during queued-evidence drain) → `SUPERVISION_UNCONFIRMED`: no focus, no prompt, no recipient, only the *unbound* reservation released, provisional fields rolled back to `targetIds: []`. (ADR-020 §5.2) — guards prompting an unwatched child — **keep**.
